## The trap that cost a whole round

The 17 Sep 00:32 build was made with plain `flutter build`/`flutter run`. That
skipped `DEFINES`, so it shipped without `TESTER_BUILD`, `LOG_RAW_TRANSCRIPTS`
**and** `CLOUD_STT_API_KEY` — which presented as three unrelated regressions:
the skip button vanishing, the mic "going berserk" (cloud STT dead → on-device
fallback → that handset has no `bn` locale), and a redacted log.

`verify_apk` now proves both flags reached the binary. You cannot grep an APK
for a dart-define — `bool.fromEnvironment` is a const, so the compiler folds it
and the name never appears — so each is proved by a string that exists only
when it is on, and one that exists only when it is off.

**Always build through the script.**

## Traps this session fell into

- **Item 46 repeated itself, in a file written after item 46 was fixed.** The
  earcon used `.timeout(d, onTimeout: () {})` on a `Future<AudioEvent>` and
  threw on every single cue. `.timeout` type-checks its callback against the
  future's *runtime* type. The fix is the one item 46 landed on: bare
  `.timeout()` with `on TimeoutException`. A try/catch meant it degraded
  silently, so item 59's tone never played in the build that shipped.
- **An empty list matched everything.** `[].every(...)` is vacuously true, so a
  recall-pass entry with no Bangla spelling matched every utterance in the app.
  Caught in a minute by existing tests; the guard now lives in the matcher
  rather than the data.
- **A fix landed on the wrong path.** Item 50's location primer went into
  `chooseRole()` — and testers press ⏩, which bypasses it entirely.
- **Streaming has never done anything for this app's users.** The code is
  correct, but the model is a thinking model, so the first chunk arrives at 99%
  of total time; and even when it streams, only the *visual bubble* updates —
  TTS speaks once, at the end. For a blind user that is zero benefit. The 3s
  spoken "still working" is the only thing actually reducing felt latency.
